## AiCaptureLevel

```ts
type AiCaptureLevel = 'none' | 'metadata' | 'redacted' | 'full';
```

How much of one kind of content reaches a stored profile. `none` keeps the figures and records
nothing of what was said, `metadata` keeps the shape (`[text omitted · 1842 chars]`), `redacted`
is the default and masks credentials and personal data, and `full` stores it verbatim with no
masking.

## AiCaptureFieldLevels

A level per content field, for the setups where one field is more sensitive than the rest.
Resolution runs from the narrowest: a field, then the group it belongs to (`prompt` covers
`instructions` and `messages`, `tools` covers the three tool fields), then `default`.
`runtimeContext` is outside that chain — the AI SDK's `runtimeContext` on a call and each tool's
`toolContext` hold the application's own state rather than what was said, so they are recorded
only when the field is named, not even by `capture: 'full'`. `providerPayload`, the raw bodies exchanged with the provider, is outside it for the same reason.

## instrumentAgentClass

```ts
function instrumentAgentClass(agentClass: unknown): boolean;
```

Teaches every AI SDK agent in the process to name itself in the profiles it produces, by wrapping
`generate` and `stream` on the agent class's prototype. `AiCollectorModule` calls it at startup
with the SDK's `ToolLoopAgent`, so an application never has to — it is exported for a host that
drives the collector itself.

This is what keeps agent attribution free of any call-site change: the application declares its
agent's identity the way the SDK already asks it to, with the `id` setting, and never imports the
profiler to get it recorded. The wrapper only reads `id` and opens an async frame around the
original call; it changes no argument, no result and no error, and agents built before it ran are
covered too since a method is looked up on the prototype at call time.

Returns whether this call instrumented the class — `false` if it was already done, or if the
installed `ai` exposes no such class.

## profileAgent

```ts
function profileAgent<A extends AiAgentLike>(agent: A, options?: ProfileAgentOptions): A;
```

The escape hatch, for the two cases `instrumentAgentClass` cannot reach: an agent that implements
the SDK's `Agent` interface itself rather than extending `ToolLoopAgent`, and an agent whose panel
name should differ from its `id`. A `ToolLoopAgent` with an `id` needs none of this.

```ts
const support = profileAgent(myCustomAgent, { id: 'support', name: 'Support agent' });

await support.generate({ prompt });
await pipeAgentUIStreamToResponse({ agent: support, uiMessages, response });
```

The returned agent is the same object to every caller, so it can be provided in place of the
original and handed to `createAgentUIStream`, `createAgentUIStreamResponse` or
`pipeAgentUIStreamToResponse` unchanged. When both apply, the wrapper's name wins over the id the
class instrumentation would have used.

Unlike the `id` route, this puts an import of this package in application code, which rules out
keeping the profiler in `devDependencies` for the file that calls it.

## AiToolOrigin

```ts
type AiToolOrigin = 'local' | 'mcp' | 'provider';
```

Where a tool comes from, which decides who runs it: `local` is declared in the application's code,
`mcp` was discovered on an MCP server at runtime, and `provider` is built into the model itself (a
provider-run web search, say) and never executes in the application at all.

## AiModelPricing

What one model charges. Rates are per `per` tokens — a million by default, the unit providers
publish. A rate left out falls back to the one it refines, so a model with no cache discount and
no separate thinking rate needs only `input` and `output`.

<AutoTypeTable path="packages/nest-profiler-ai/src/ai-pricing.ts" name="AiModelPricing" />

## AiPricingTable

```ts
type AiPricingTable = Record<string, AiModelPricing>;
```

Prices by model. A key is `provider:model` (`openai:gpt-4o-mini`) or the bare model id
(`gpt-4o-mini`), matched in that order and case-insensitively. A provider arrives qualified by its
transport (`openai.responses`), and its root is tried too.

## AiPricingSource

```ts
type AiPricingSource = () => AiPricingTable | Promise<AiPricingTable>;
```

Loads a price table from wherever the prices live. Called when the module starts and, once
`pricingTtl` has passed, again in the background — never on the path of a model call.

## fetchOpenRouterPricing

```ts
function fetchOpenRouterPricing(options?: OpenRouterPricingOptions): Promise<AiPricingTable>;
```

Reads the prices of every model OpenRouter serves, ready to hand to `pricingSource`. The list is
public, so no key is needed. Model ids come back as OpenRouter writes them (`openai/gpt-4o-mini`),
which is what the AI SDK reports for a call that went through OpenRouter.

## estimateCost

```ts
function estimateCost(
  usage: AiTokenUsage | undefined,
  provider: string,
  model: string,
): number | undefined;
```

What a call cost, from its token counts and the configured prices — `undefined` when the model has
no price. Cached and thinking tokens are billed at their own rate and are already counted in the
input and output totals, so each is taken out before its rate is applied. The collector applies
this itself; call it directly only to cost something of your own.

## mcpToolNamesOf

```ts
function mcpToolNamesOf(tools: unknown): Set<string>;
```

The names of the MCP tools in a tool set, told apart from local ones by the marks `@ai-sdk/mcp`'s
client leaves on every tool it builds. The collector calls it on each operation's start event — the
last point at which a tool still says where it came from, since the provider only ever sees names
and schemas — so tools discovered through that client are labelled `mcp` with nothing declared.

## markMcpTools

```ts
function markMcpTools(names: readonly string[]): void;
```

Declares tool names as coming from an MCP server. Only needed for an integration that builds its
MCP tools itself rather than through `@ai-sdk/mcp`'s client, which `mcpToolNamesOf` recognises on
its own. Call it once after loading a server's tools.

Unlike the automatic path, this puts an import of this package in application code, which rules out
keeping the profiler in `devDependencies` for the file that calls it.

## AI_ENTRYPOINT_TYPE

```ts
const AI_ENTRYPOINT_TYPE = 'ai';
```

The `Profile.entrypoint.type` a profiled HTTP request is promoted to once it has called a model.
